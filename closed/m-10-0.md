# m-10-0 `vc-x1 push` invokes `fn snapshot()`, which drops the files the size limit refused

A session's transcript in our agent-repo went over `snapshot.max-new-file-size` before its first
push, and `vc-x1 push` committed and pushed both repos without it and without a word. The `jj`
command reports the same case as `Refused to snapshot some files`. We think it is a bug in
vc-x1, and we found it at our close-out.

## What happened

- The session started at 2026-10-15T18:27Z. Its transcript, a new file in the agent-repo, went
  over the limit, then 10 MiB in wink's user config, at 21:38Z.
- Only `vc-x1 push` snapshots our agent-repo, and the session's first push was at 21:51Z, so the
  file was a new file over the limit at its first snapshot. A file already tracked grows past
  the limit freely, so this hits only a session that outgrows the limit before its first push.
- That push's review listed `settings.local.json` alone under `.claude`. The closing push,
  22:24Z, listed `0 files changed` with `bot_had_changes=false` and
  `push commit-bot: skip`, and reported `completed all stages (verified)`.
- wink saw the warning from a plain `jj st` in the agent-repo, the limit went to 20 MiB, and a
  `vc-x1 push main` at 23:42Z committed the transcript as agent-repo `rlultmpqklku`.

## Where it is dropped

`RepoSession::snapshot` discards the list `snapshot_with` returns, the new files the limit left
untracked, with their sizes:

https://github.com/winksaville/vc-x1/blob/14adcb34e7033a94ee5fa01fc20f48bee0318f03/src/jj/session.rs#L281-L283

```rust
pub fn snapshot(&mut self) -> Result<()> {
    self.snapshot_with(None).map(|_| ())
}
```

The list is built from jj-lib's `untracked_paths` at
[session.rs#L411](https://github.com/winksaville/vc-x1/blob/14adcb34e7033a94ee5fa01fc20f48bee0318f03/src/jj/session.rs#L411),
and `commit_any_size` already uses it, but no caller of `snapshot` sees it, push's included.

## What we propose

`snapshot` keeps its `Result<()>` and returns an `Err` when the list is not empty, a typed error
carrying the paths and sizes, so push can print them with jj's two remedies, a `.gitignore`
entry or a larger `snapshot.max-new-file-size`, and a caller can match on it:

```rust
pub fn snapshot(&mut self) -> Result<()> {
    let too_large = self.snapshot_with(None)?;
    if !too_large.is_empty() {
        return Err(SnapshotError::FilesTooLarge(too_large).into());
    }
    Ok(())
}
```

- Every caller fails with it, the read-only ones in `lookup.rs` and `jj.rs` included. We think
  that is right, since a working copy missing a file is wrong for every verb and the `jj`
  command warns on every one.
- `commit_any_size` calls `snapshot_with` directly and keeps letting a file of any size in.
- `snapshot_working_copy` commits the snapshot operation before returning the list, so on the
  error the files that fit are already snapshotted. Harmless, but the message should say so.
- For the agent-repo, whose transcripts are its content, push may want `commit_any_size`, or a
  per-repo limit that `vc-x1 init` sets. That is yours to weigh.

## An agent-files check, for v0.2.9 if it fits

The agent missed both signs in its own push output. A live session always changes its own
transcript, so an agent-repo with nothing to commit during a session is never right. We propose
a line under Before any push: the review shows the agent-repo carrying the session's transcript,
and when it does not, stop and ask.
