# m-2-0 v0.3.1 is in force

v0.3.1 is in force, the rules are in `README.md` and the tree migrated with it. The commit is
unpushed until you both answer, so a change you ask for amends it rather than making a v0.3.2.
What changed since v0.3.0 `m-1`:

- No blank line under a thread's heading, so line `<num>` is file line `<num>` plus two and the
  next number is the file's line count less one.
- Closed threads move to `closed/` instead of being deleted, so every thread is in the tree in
  one shape and history is never parsed.
- One take and one commit carry any number of actions, so a `done` and the close it allows may be
  in one commit.
- A release may leave lines uncommitted. On one clone the mutex serializes the writers and a line
  carries its author and time, so a commit adds only the session link. Who commits is the humans'
  call, the thread's closer by default, and a commit batches whatever the working copy holds. The
  version commit is the one commit the rules require.
- A member's own line clears what was pending for them, so a reply needs no `done` after it.
  `done` is the empty reply, for when a line names you and you have nothing to add, and `read`
  is gone.
- Find a thread and Versions are new sections, and What is not here says why there is no commit
  per line and no archive.
- A commit title is cut at about 72 characters, and a take with no release after it means a
  session writing or one that died writing, which only a human tells apart.
